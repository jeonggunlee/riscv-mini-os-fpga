ONE INSTRUCTION

sb gp, 0(ra)는 어떻게 UART 문자가 되는가?

  1. 1
    Fetch

    PC가 가리키는 00308023을 읽는다.

  2. 2
    Decode

    S-type, byte store, rs1=x1, rs2=x3.

  3. 3
    Address

    ALU가 x1 + 0 = 0x1000_0000 계산.

  4. 4
    Bus write

    wstrb=0001, 하위 8비트가 MMIO로 전달.

  5. 5
    Serialize

    UART가 start + 8 data + stop bit를 D4 핀으로 송신.

instruction → control signals → address/data bus → peripheral → physical pin

ISA vs ABI

CPU의 명령 계약과 compiler의 사용 규칙

ISA · -march=rv32i

CPU가 이해하는 명령과 encoding을 정한다.

  • 32-bit integer registers
  • ADD, LW, SW, BGEU, JAL…
  • compressed/M extension은 생성하지 않음
ABI · -mabi=ilp32

compiler가 register와 자료형을 쓰는 규칙이다.

  • int, long, pointer = 32 bit
  • a0–a7: 인자, a0–a1: 반환값
  • sp=x2, ra=x1 · 표준 stack 정렬 16 byte
a3x13 · 주소 basea4x14 · loop ia5x15 · sumzerox0 · 항상 0

ABI 이름은 별칭이다. 예: a5와 x15는 동일한 물리 register다.

ADDRESS RESOLUTION

%hi, %lo, .LANCHOR0의 의미

ASSEMBLY SYMBOL.LANCHOR0

GCC가 만든 sum_limit 주소 대표 symbol

linker.ld가 배치
FINAL ADDRESS0x0000_0068

ELF에서 확정된 실제 byte address

lui a5,%hi(.LANCHOR0)
lw  a5,%lo(.LANCHOR0)(a5)
lui x15,0x0
lw  x15,104(x15)

// Memory[0x68] → x15

%lo는 signed 12-bit 값이다. 하위 값이 음수이면 %hi가 이를 보정한다. 예: 0x1800 = (2 << 12) + (−2048). 현재 0x68에는 보정이 필요 없다.

왜 BRAM 사용량은 0인가?

single-cycle CPU가 같은 cycle에 instruction/data를 조합식으로 읽고 byte write까지 요구한다. Vivado는 8 KiB 메모리를 dual-read distributed RAM으로 구현했다.
